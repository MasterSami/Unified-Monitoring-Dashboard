01 · The Problem

Monitoring is scattered across silos

A NOC engineer jumps between four separate systems to understand a single incident — each tool has its own console, severity language, and inventory.

Zabbix
console #1
Dynatrace
console #2
NNMi

Different severity language per tool · duplicate hosts across tools · no unified inventory or view.

02 · The Idea

What if it were all in one place?

Instead of opening four screens, open one — see every host and alert across all tools, in one language, while each tool keeps its own native severity.

  • One view for all hosts and all alerts
  • Correlate across tools (the same server seen in multiple sources)
  • Know each source's health — see the moment a feed stops

03 · The Solution

Unified Monitoring Dashboard

A web app that pulls data from each tool, normalizes it into one shape, and presents it in ready-made views — with multi-instance support per tool.

Unified normalization

Every tool maps into the same Host / Alert schema.

Multi-instance

Zabbix-34/140 · NNMi-12/13/76 · SiteScope-141/34/140.

Native severity

NNMi stays Critical/Major, Zabbix Disaster/High… each in its own words.

Source health

Collector health — a stalled feed shows up immediately.

07 · Safety

SiteScope: a critical production server — zero touch

The SiteScope integration is designed so the production server is never affected in any way.

  • Read-only log reads — the service and the Netcool probe keep running normally
  • Credentials are redacted on the box before a single line leaves it
  • No service restart · no config change · no log deletion · no firewall change
  • State-wins-over-severity for dirty data · metric-less events are flagged, not dropped

08 · Data Model

Five tables · one shape

No table per tool — a source_platform column separates them, and a composite unique key makes every upsert idempotent.

hosts

All servers + capacity metrics.

alerts

All alerts + SiteScope fields.

collector_runs

Per-source health.

topology_nodes / edges

Nodes and links.

UNIQUE (source_platform, source_instance, external_id) — the same row updates, never duplicates.
